# Deploying Lyric Match

Three pieces: Supabase (optional database), Render (Flask API) and Cloudflare Workers (static frontend). Do them in this order. Dashboards change often; where a step depends on current UI, follow the provider's current docs rather than exact button names.

## a) Supabase (optional)

Skip this and the game still works; the leaderboard is just switched off and snippets are cached in memory only.

1. Create a project in the Supabase dashboard.
2. Open the SQL editor and run the contents of `backend/supabase/schema.sql`. It is idempotent. It creates the `snippets` and `scores` tables, enables RLS with no policies, and adds the `score_rank` function.
3. Copy the **project URL** and the **service-role / secret key** (check the current Supabase docs for where API keys are shown). The key is for the server only: never put it in the frontend or commit it.

## b) Render (backend)

1. In Render, create a **Blueprint** from this GitHub repo. It reads `render.yaml` (web service `lyric-match-api`, free plan, root directory `backend`, one Gunicorn worker, health check `/healthz`).
2. Fill the variables marked `sync: false`:

   | Variable | Value |
   | --- | --- |
   | `GEMINI_API_KEY` | Google AI (Gemini) API key. Primary LLM. |
   | `OPENAI_API_KEY` | OpenAI API key. Fallback LLM. Optional if Gemini is set. |
   | `SUPABASE_URL` | Project URL from step (a). Leave empty to run without a database. |
   | `SUPABASE_SERVICE_ROLE_KEY` | Service-role / secret key from step (a). |
   | `ALLOWED_ORIGINS` | `https://lyrics-match.driptobhattacharyya.com` (comma-separate more origins if needed). |

   `SECRET_KEY` is generated by Render. `GEMINI_MODEL`, `OPENAI_MODEL` and `MAX_LLM_CALLS_PER_DAY` (200) have defaults in `render.yaml`.
3. Deploy, then open `https://<your-service>.onrender.com/healthz`. It should return `{"status": "ok"}`. The free tier sleeps when idle, so the first request after a pause is slow; the frontend handles this with a warming screen.
4. Note the service URL; step (c) needs it.

### Optional: pre-generate snippets

Pre-generating reduces LLM calls in production. Run it locally, from `backend/`, with `GEMINI_API_KEY` / `OPENAI_API_KEY` and the Supabase variables in `backend/.env` (so snippets are written to the `snippets` table):

```bash
python scripts/pregenerate.py --pack hi-indie --limit 50 --variants 2 --max-calls 100
```

Re-running is safe: existing snippets count toward `--variants`. Use `--no-supabase` to write only the local file `data/snippets.json`.

## c) Cloudflare Workers (frontend)

1. Your domain must use Cloudflare DNS for the custom domain step.
2. In the Cloudflare dashboard, create a Worker by connecting this GitHub repo with **Workers Builds** (check the current Cloudflare docs for the exact flow).
3. Build settings:
   - Root directory: `frontend`
   - Build command: `bun install && bun run build`
   - Deploy command: `bunx wrangler deploy` (the `deploy` package script also builds first, so either works)
4. Set a **build variable** `VITE_API_URL` to the Render service URL (no trailing slash). It is read at build time, so rebuild after changing it.
5. Add the custom domain `lyrics-match.driptobhattacharyya.com` to the Worker (Settings, Domains & Routes; check the current docs).
6. The Worker name comes from `frontend/wrangler.jsonc` (`lyric-match`); it serves `dist/` as static assets with single-page-app fallback.

## d) Spend limits and alerts

The app has a daily LLM call cap and rate limits, but also set caps in the provider consoles:

- Google AI / Gemini: set a budget or quota and an alert.
- OpenAI: set a monthly budget limit and usage alerts.
- Render and Supabase: review the free-tier limits and billing alerts.

## e) Retire the old Firebase site

Once the new site works, disable the old hosting. Either run

```bash
firebase hosting:disable --project <project-id>
```

or delete the project in the Firebase console. Remove any links to the old address elsewhere.

## f) Post-deploy checklist

- [ ] `/healthz` on the Render URL returns `{"status": "ok"}`.
- [ ] `/api/meta` lists the packs and shows `"leaderboard": true` if Supabase is configured.
- [ ] https://lyrics-match.driptobhattacharyya.com loads and starts a round with real lyrics (no CORS error in the browser console, so `ALLOWED_ORIGINS` matches exactly, with no trailing slash issues).
- [ ] Finish a game and submit a score; it appears on the leaderboard.
- [ ] Supabase tables show RLS enabled with no policies.
- [ ] Spend limits and alerts are set at the LLM providers.
- [ ] Old Firebase site disabled.
